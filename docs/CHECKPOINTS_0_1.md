## Checkpoint 1: implementation

- Removed Home Buyers markup, audience tab handling and obsolete audience styles. The default planner opens Traffic & Emissions; `#urban-planners` and `#intersections` still open that mode, `#stormwater` opens Stormwater directly. Search and map-site selection remain available in both modes.
- Sidebar focuses on selection, question/Analyze and review. Evidence/manual adjustments, map settings and the development preview are expandable. Analyze is visible before selection and enabled after selection.
- `proposal.py` defines a strict Pydantic contract: site/workflow/revision, source references, design parameters, local geometry, geometry references, metrics, input hash, assumptions, access/overlap findings and recommendation. Validation rejects mixed revisions, missing geometry references and invented values for unassessed metrics. Future physical design types must extend this contract; CP1 supports only explicit test geometry.
- `/api/proposal-fixture` deterministically generates a small synthetic rectangle in UTM 11N and measures its area, then returns WGS84 display geometry. No model or sponsor calls are made. The endpoint is exclusively a development fixture, never a fallback for a provider failure.
- `public/proposal.js` publishes geometry, area and revision together. Show proposal toggles only that layer. Revisions preserve the previous published layer until ready; site/mode changes invalidate pending requests and remove unrelated results. Input changes mark the prior fixture stale. Purple dashed design style differs from source evidence and county boundaries. Benefits, parcel overlap and access remain unassessed.
- The real-data requirement disables the old assumed-demand emissions discovery layer. Vexcel imagery, optional Esri labels, CoStar points/search and county watershed/rainfall remain.
