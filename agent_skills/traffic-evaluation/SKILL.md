---
name: traffic-evaluation
description: Inventory current traffic evidence and verified simulation inputs; evaluate bounded street alternatives without inventing demand or emissions.
---

Call read_traffic_inputs and query_neighborhood_discovery when available. Keep current estimated speed and free-flow ratio separate from verified historical turning demand. Speed snapshots cannot supply turning ratios, volume, annual emissions or recurring congestion. Report missing inputs explicitly. As the domain specialist, produce an input inventory with exact cited facts and no recommendations or invented layout dimensions; the application saves /project/reports/domain-analysis.json. As lead, use both saved specialist reports and planner constraints to select two or three distinct supported layouts. Call evaluate_designs only once. Respect the returned feasibility checks and ranking; failed or unassessed outcomes remain so. Never rerun a simulation to seek favorable random outcomes. Keep notes within your assigned notes directory.

As the lead on continuation, read the curated previous_traffic_evaluation in /project/brief.json. It contains historical evaluated layouts and facts, not current flow. Use the lead's evaluate_designs changes argument for named parameter revisions; omitted alternatives and parameters remain. Retain canonical map constraints. Explain a meaningful change against its previous verdict without reusing old metrics as new results. New evaluations use environmental-priority-v1: all hard gates first, then total modeled CO₂, followed by feasibility and disruption when environmental differences are within the declared comparison tolerance. Data readiness is reported separately. Never loosen gates, substitute demand from a different intersection, or claim that current speeds establish turning demand. A valid rejection is a useful saved evaluation.

As the domain specialist, use /project/source-brief.json for current inputs and /project/constraints.json for user constraints. Do not read prior evaluation history; the lead handles revisions. Return a short current-source inventory with only the most consequential cited facts.

When read_street_design_context and read_street_design_guidance are available, call both regardless of turning-count availability. Research the actual mapped anchors and the relevant FHWA crossing, refuge and road-space guidance, alongside the source neighborhood/traffic evidence. Keep geometry readiness separate from performance readiness. The lead uses this research to create a physical overlay with create_or_revise_road_concept; this does not require a simulation. Explain useful source conditions and missing checks without choosing invented dimensions or claiming local effects from general guidance. The saved domain report includes the anonymous anchor inventory for the lead.

When the lead has create_or_revise_road_concept, follow the traffic-concept skill for the primary map deliverable. Simulation is optional and only used when the planner explicitly requests quantitative comparison. A concept is not a tested alternative; a separate traffic verdict cannot establish the concept's performance.
